# Sapling 网页端检测替代方案

## 结论

可以改，但网页端不是公开接口。阿里云线上需要运行一个带持久化登录态的 Chromium/Playwright worker，通过 Sapling 检测页面填入文本、点击检测、读取 `Fake` 百分比。

## 线上改动

1. 新增 `sapling_web` 检测适配器，保留现有 `sapling` API 适配器作为回退。
2. ECS 安装 Chromium 和 Playwright，使用独立 profile 保存 Sapling 登录态。
3. 由单 worker 串行执行网页检测，限制并发，避免页面状态互相覆盖。
4. 增加登录态失效、页面结构变化、超时和验证码状态；失败时返回明确错误并回退 API 或规则检测。
5. 配置改为 `AI_DETECTOR_ADAPTER=sapling_web`，并增加检测来源字段。

## 风险和成本

- 需要在 ECS 上人工登录一次，登录态可能过期，网页结构也可能变化。
- 网页端通常有长度限制，长文本需要分块；分块合并口径必须固定。
- 单次耗时和稳定性会明显差于 API，不适合高并发。
- 需要先做小流量灰度，确认账号权限和网页端条款允许自动化。

当前线上代码仍使用 Sapling API；本文件是替换前的实施方案，尚未部署网页 worker。
